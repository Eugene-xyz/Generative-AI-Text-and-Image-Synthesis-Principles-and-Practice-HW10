# 實際執行後的反思

日期：2026-11-22，Asia/Taipei。已完成一條真實路徑：6 份明列範圍來源 → 23 頁 Wiki → 經討論確認的 graph／大綱／整份內容 → 18 頁 HTML → 實際瀏覽器檢查與修正。以下是根據紀錄整理的作業反思，不捏造使用者的個人心得。

## 哪個節點最常出錯？

**這次簡報製作中，問題最多的是 J「把核准內容轉成 HTML」：3 個獨立問題，都在 K 瀏覽器檢查發現。** 分別是換行解析造成文字空白、角色頁在小桌面被導覽列遮到，以及測驗頁粗體符號沒有正確呈現。內容在 Markdown 中正確，不代表轉換後也正確。

統計以「同一根因」為一次；18 頁一起漏文算一次，不把每頁、每次複查各算一個錯誤。範圍是已有明確 ID 的正式入庫與後續簡報紀錄：

| 根因所屬階段 | 獨立問題數 | 問題與依據 |
| --- | --- | --- |
| Wiki 整理／來源定位與引用 | 3 | E01 章節定位、E02 混合來源標籤、E05 攔網高度措辭；[正式入庫紀錄](checks/ingest-2026-11-22.md) |
| E／F 逐頁內容與 Wiki 對齊 | 1 | CT01 圖解需要的場地範圍與量測端點；[內容檢查](checks/content-review-2026-11-22.md) |
| J HTML 內容與版面轉換 | 3 | HTML01–HTML03；[HTML 實測](checks/html-review-2026-11-22.md) |
| G 圖解與核准文字對齊 | 1 | D01：文字說移到網前，C 的落點卻在攻擊線後；最後讀圖才發現 |
| 取得工具／檢查器，另列 | 3 | E03 官方網頁讀取逾時、E04 Windows 路徑誤報、QA01 hash 導覽保留展開狀態造成版面誤判 |

如果問「哪個**檢查節點發現**最多」，K（含最後圖文閱讀）本次抓到 3 個 HTML 問題、1 個圖解問題和 1 個檢查器問題，共 5 類；正式 Wiki 檢查發現 E01／E02／E04／E05 共 4 類。若只計內容／產物，Wiki 整理與 HTML 各 3 個，也不能說 HTML 在整個專案中明顯較差。這是一次小規模執行的觀察，不足以推定所有 LLM Wiki 的錯誤分布。

前置階段曾遇雙欄文字交錯，並比對舊教練手冊與新規則；這些記在原始審閱紀錄，不重複當成此表中的新事件。來源之間存在版本差異，也不等於 AI 寫錯。

## 發現後，把檢查往前移到哪裡？

最明確的例子是 HTML01。原先是在 K 開瀏覽器才發現「有圖、有標題，卻沒有主頁文字」。根因是 Windows 換行格式與解析器分段方式不一致。

原流程：核准內容 → 製作 HTML → 開瀏覽器才發現空白 → 修解析器。

調整後：核准內容 → **J0：統一換行、檢查 H2 與 18 頁、確認每頁主頁／補充／講解提示／圖解規格／頁尾來源皆非空** → 才輸出 HTML → K 再比對核准稿並實際操作。

這樣能在建置時就攔下明顯漏文，避免先花時間測沒有內容的頁面。仍然保留 K，因為「不為空」並不能證明文字完整、圖正確或小視窗可讀。角色頁和粗體問題就是仍需要實際呈現檢查的例子。D01 更清楚：程式檢查當時已通過，但讀圖仍發現 C 沒有真的畫在文字所說的網前；因此圖解語意不能只看文字有沒有越界。

較前面的改善也有依據：S02 雙欄交錯後，摘要前加入原頁與分欄複查；E01 後加入目錄、章首頁、頁碼交叉確認。**版本及賽事範圍的檢查原本就安排在 ingest 前**，所以不將它寫成完成後才發現的流程改進。

## 有沒有修改 workflow／graph？為什麼？

有。大綱及整份內容的 H1／H2 討論節點保留，因為它們確認的是教學方向與內容，不能由自動化測試代替。本輪只把 J 的建置前檢查明列為 J0，形成 [graph v1.1](slides-graph.md)；保留 [原 v1.0 快照](slides-graph-v1.0.md) 方便比較。J0 失敗回到解析／內容輸入，K 的版面或互動問題回 J，圖解問題回 G，知識問題則回 E 或 Wiki。

另外，K 的測試方式改成兩種情境分開：先重新載入未展開的頁面檢查主頁，再展開答案檢查捲動可達。之前只換 hash 會保留已展開狀態，導致把正常變長的內容當成初始版面錯誤。這是檢查方法修正，不是為了讓結果好看而取消可讀性要求。

## 修改後有沒有再執行？

有。統一換行與非空檢查加入後已重新建置；2026-11-22 16:58:19 +08:00 的 [瀏覽器複查](checks/html-2026-11-22/final/browser-results.json) 為 182 項通過、0 失敗，涵蓋全部 18 頁與三種視窗、內容對應、操作及來源路徑。最後圖幅與紀錄更新的 [局部交付複查](checks/html-2026-11-22/delivery/browser-results.json) 有 18 項通過，且以記憶體樣本確認空白主頁會被 J0 拒絕、LF 與 CRLF 結果相同。隨後讀圖發現 D01，沿既有 K→G 修正並完成 [受影響範圍再檢查](checks/html-2026-11-22/delivery-recheck/browser-results.json)：19 項通過，修正後圖面亦已重新閱讀。

這證明本次修正後的產物可通過所列檢查；還沒有藉多次獨立專案衡量錯誤率是否下降。教學時間仍是 18:20 的預算，真實初學者理解、真人試講與未測瀏覽器仍需另外驗證。
